release: v0.6.2 — manual "Update now" button for systemd agents

Patch release shipping the on-demand agent push. Auto-update only
fires at WS reconnect, so a stably-connected agent could sit on an
old version indefinitely. The new button lets admins force a push
from the Hosts settings tab without SSHing into the target to
`systemctl restart` first.

Added
- POST /api/hosts/:id/force-update — bypasses the auto_update +
  cooldown + version-compare gates and pushes the current hub
  bundle over the live WS. Keeps the install_mode=systemd guard
  (Docker bundles are baked into the image, can't be replaced from
  inside) and a live-connection guard (409 if the agent isn't
  currently connected).
- agentIngestWS now keeps a Map<host_id, WebSocket> registry,
  populated at connection time and cleared on close. Reconnects
  evict the previous socket before storing the new one so a stale
  WS can't accidentally receive a push.
- hostsStore.forceUpdate(id) is the matching client action.
- ForceUpdateButton in HostsSettingsTab (DownloadCloud icon, sits
  before AutoUpdateToggle). Disabled with explanatory tooltip when
  install_mode != systemd or the agent is offline.
- i18n keys added to fr.json + en.json (force_update,
  force_update_unsupported, force_update_offline, force_update_sent,
  force_update_failed).

Reverted
- The FleetChart "filter hosts with no live samples" change is
  rolled back. It hid legitimate hosts during the WS-warmup window
  after page load. The original "index-0 host's solid line is
  invisible when the local hub has no sidecar" UX issue stays open
  and will be addressed in a follow-up patch.

Why this matters
- Without this button, the only way to push a new bundle was to
  wait for an unplanned agent reconnect (network blip, hub restart,
  systemd Restart=on-failure). On a stable mesh of agents that's
  essentially never. The button gives admins immediate control
  without losing the existing auto_update safety rails.

Upgrade
- Hub: `docker compose pull && docker compose up -d`.
- Agents: click the new DownloadCloud icon in Settings → Hosts.
