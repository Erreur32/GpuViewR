release: v0.4.2 — hostname robustness, single-vendor composes, log hygiene

Five things picked up during the deb13 / Jarvis cross-vendor test
loop after v0.4.1 shipped. None are user-facing features — all are
sharp-corner fixes you only notice once you actually try to install
on two boxes side by side.

Hostname inside the container
- The label backfill in seedLocalIfMissing only kicked in when the
  existing row had label === 'local'. But on the first v0.4.0 boot
  it had already been written as the (container-id) os.hostname()
  value, so the v0.4.1 upgrade silently kept the container id even
  after hostHostname() learned to read /host/proc. New condition
  accepts three "auto-set" shapes: 'local', label === hostname, or
  a 12-hex-char Docker container id. User-customised labels are
  still preserved.
- /proc/sys/kernel/hostname is a pseudo-virtual file whose value
  follows the reading process's UTS namespace, not the procfs
  mount-point — so on some kernels the /host/proc bind-mount still
  returned the container id. New resolution chain in
  server/utils/hostHostname.ts:
    1. HUB_HOSTNAME env       explicit override, beats everything.
    2. /host/etc/hostname     bind-mounted static file (added to all
                              compose variants), kernel-independent.
    3. /host/proc/sys/kernel/hostname   best-effort.
    4. os.hostname()          last resort.
- Dashboard header gained a HostChip showing the resolved hostname
  + a "Hub" pill when the row is LOCAL_HOST_ID, so users on mono-
  host installs (where the HostSelector dropdown self-hides) finally
  see which box they're looking at.

docker-compose files
- New docker-compose.nvidia.yaml mirrors the AMD recipe: NVIDIA
  Container Toolkit passthrough enabled out of the box. The vendor-
  neutral docker-compose.yaml still ships with passthrough commented
  out — it's the aggregator-only case. Quick start in the README
  now offers all three (nvidia / amd / aggregator) as parallel curl
  recipes, no uncommenting required.
- Rename .yml → .yaml across all five compose files (YAML.org spec
  preference; Docker Compose v2 auto-discovers .yaml first). Old
  .yml symlinks lived for a few hours, then got dropped on user
  request — purely aesthetic. Old wget URLs at /main/*.yml 404; tag
  snapshots still resolve.

Log hygiene & reconnect storm
- Hub-side: the agent rate-limit warning logged once per offending
  frame while the close round-tripped, producing 80+ identical lines
  per disconnect. Now logged exactly once per session, with the
  actual frame rate measured.
- Agent-side: flushBuffer() drained the entire offline-replay queue
  in a single tight loop on every reconnect — after a long outage
  that exceeded the hub's 100-frames/s rate limit and triggered an
  endless reconnect→kick storm. Chunked drain (50 frames per 600 ms)
  stays under the ceiling and yields to live tick frames between
  batches.

UI polish
- System page "GPU" subtitle no longer claims "Accélérateurs NVIDIA
  remontés par nvidia-smi" on AMD hosts. Hub badge added to the
  System page Host card title. hosts.section_help +
  hosts.hub_badge_help mention both smi binaries. Boot banner says
  "Real-time NVIDIA / AMD GPU Dashboard".
- no_gpu UI placeholder mentions rocm-smi as a possibility and
  points at GPU_VENDOR + the hub boot logs.

Docker
- Hub Dockerfile now bakes agent/dist/agent.mjs + install.sh.tpl
  into the runtime image. /install.sh + /agent.mjs no longer 503
  out of the box — the curl-install path for remote agents works
  on first boot.
- docker-entrypoint.sh probe is vendor-aware (GPU_VENDOR-driven)
  instead of hardcoding nvidia-smi.

Typecheck + hub build + agent build + 39 server tests + 8 agent
tests all green; behaviour validated end-to-end on Jarvis (AMD Strix
Halo) and deb13 (NVIDIA) with the agent-on-deb13 hub-on-jarvis
cross-pollination.
