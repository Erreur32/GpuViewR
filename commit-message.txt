release: v0.6.8 — Dockerfile hotfix for the Windows installer endpoint

v0.6.7 shipped install.ps1.tpl in the repo and wired up
GET /install.ps1, but the hub Dockerfile only COPY'd install.sh.tpl
into the image. The endpoint responded with 503 and
"# install.ps1 template not found in this build" to every user
who pasted the Windows one-liner from the Add Host modal.

Caught the moment the first real Windows user (PapoMint on
192.168.32.210) tried the new flow. Pure build-recipe omission,
no code change — just the missing COPY line.

Fixed
- Dockerfile: added COPY --from=builder /app/agent/install.ps1.tpl
  ./agent/install.ps1.tpl next to the existing install.sh.tpl line.

Upgrade
- Hub: `docker compose pull && docker compose up -d` (the `latest`
  tag rebuilds on every push to main, so this fix lands as soon as
  CI completes the image push to ghcr.io).
- Agents: no change required.

Why this slipped past local tests: the Linux install path uses
install.sh.tpl which was already in the image, so end-to-end
testing on Linux didn't exercise the missing file. The first real
exercise of the new PowerShell endpoint was the user's VPN'd
Win10 box pasting the modal command — exactly where the missing
COPY surfaced.
