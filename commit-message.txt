release: v0.1.25 - real MQTT test, no more spurious "Bad Gateway"

Fixed:
- MQTT "Send test" now opens its own short-lived connection with
  the configured URL/credentials and publishes a test message,
  instead of polling the long-running client's connected flag.
  The old check raced the background reconnect right after Save
  and returned "MQTT client not connected" while the handshake
  was still in flight.
- POST /api/exports/:kind/test always returns HTTP 200 with the
  { ok, message } body. The previous 502-on-failure path made the
  client's api() throw with res.statusText ("Bad Gateway"),
  swallowing the actual broker reason (auth refused, timeout,
  connection refused). The UI now shows the real message.
