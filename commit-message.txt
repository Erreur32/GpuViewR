release: v0.6.0 — sysfs-direct AMD GPU backend + processes throttling

Performance release for AMD agents. GPU samples no longer spawn
rocm-smi on the hot path — the new sysfs backend reads
/sys/class/drm/card*/device/ directly, cutting per-tick wall time
from ~80-130 ms to under 1 ms. On idle AMD hosts this drops the
agent's CPU baseline from ~0.2-0.4 core to near-zero.

Added
- Sysfs-direct GPU collector for AMD (createAmdgpuSysfsCollector).
  Discovers amdgpu cards via /sys/class/drm/card*/device/uevent
  (filters out connector entries and cards bound to other drivers),
  reads gpu_busy_percent, mem_info_vram_{used,total}, pp_dpm_sclk
  (active level), hwmon temp1_input + power1_average. Reuses the
  rocm parsers' DEVICE_NAMES table and ROCm-${pciBus} uuid scheme
  so the UI's per-process React keys stay stable across the switch.
- GPU_BACKEND env (auto|sysfs|rocm-smi, default auto). Probes sysfs
  first and falls back to the legacy rocm-smi collector only if no
  amdgpu card is discovered — safe upgrade for hosts where /sys is
  masked or the driver isn't loaded.
- PROCESSES_TICK_MS env (AMD only). Decouples rocm-smi --showpids
  cadence from TICK_MS. Default max(2000ms, TICK_MS * 2) halves the
  Python-script cost on the process collector path while keeping
  the process list refresh visibly snappy.

Changed
- docker-compose.agent.amd.yaml documents the new env vars and
  notes that /opt/rocm is only needed when FEATURES=processes is
  enabled. The sysfs path requires only the amdgpu kernel driver.
- README pre-requisites for AMD updated accordingly.
- createRocmGpuCollector gained an inflight guard (same pattern as
  processesRocm) to prevent tick pile-up if a slow rocm-smi call
  momentarily exceeds TICK_MS.

Tests
- 8 new tests (agent/src/collectors/gpuAmdgpuSysfs.test.ts): card
  discovery filtering, pp_dpm_sclk active-level parsing, uevent
  parsing, full sample mapping with a fake /sys tree (Strix Halo
  device IDs).
- New parseGpuBackend tests in config.test.ts.
