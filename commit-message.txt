release: v0.8.0 — fix master missing on /fleet 1h/24h, color-by-host chart redesign

Closes two /fleet bugs the user surfaced post-v0.7. Minor bump
because the persistence behaviour for LOCAL_HOST_ID changed (local
samples now land in gpu_metrics, were silently skipped before).

Bug 1 — master host missing from /fleet 1h/24h ranges
- agentMetricsPersistor.ts:38 skipped every sample whose host_id
  matched LOCAL_HOST_ID. That skip was defensive code from v0.4
  where the hub ran its own gpuCollector that persisted local
  samples inline before re-emitting them on the bus, so the skip
  prevented double-writes.
- v0.5 removed gpuCollector — the local sidecar has been the ONLY
  producer of local samples since. The skip silently dropped every
  local sample from gpu_metrics.
- Live charts didn't show the symptom (they read in-memory store);
  1h/24h charts did (they read SQLite history that was being
  skipped). The user noticed: "sur les autre filtre personne, on
  ne vois que les agent".
- Fix: removed the skip. Updated the persistor unit test that
  asserted the old behaviour to assert the new one (local samples
  must land in gpu_metrics + a device row gets upserted).

Bug 2 — multi-host chart unreadable
- Pre-v0.8 the FleetChart painted each curve in its metric's
  colour and distinguished hosts via a dash pattern (solid for
  host 0, long-dash for host 1, dotted for host 2, …). Above 2
  hosts the dashes became hard to track. User feedback: "les
  trait tillés ça fait moche, uniformise couleur par machine".
- New design:
    - 10-color palette indexed by host (blue / green / orange /
      purple / red / teal / yellow / pink / indigo / lime),
      assigned in order of hostsWithData.
    - All curves SOLID — HOST_DASH array dropped entirely.
    - Metric distinction now via line width: utilization 2.25px
      (headline), temperature 1.5px, power 1px.
    - Total mode (single curve per metric) keeps the original
      metric-coloured behaviour since there's no host
      distinction to convey.
    - Metric chips show line-width previews (neutral colour in
      per-host mode, metric colour in total mode).
    - Per-host legend swatch swapped from a dashed line preview
      to a solid bold line in the host's colour. HostDashSwatch
      renamed to HostColorSwatch.

Files
- server/services/agentMetricsPersistor.ts: dropped LOCAL_HOST_ID
  import + skip + obsolete v0.4-era comment.
- server/services/agentMetricsPersistor.test.ts: test flipped
  from "samples are skipped" to "samples ARE persisted", asserts
  +1 metric row and 1 device row after a LOCAL sample comes in.
- src/components/fleet/FleetChart.tsx: HOST_PALETTE +
  hostColor() + METRIC_WIDTH constants. Header comment rewritten
  to reflect the new contract. Metric chip rendering, ChartPlot
  stroke selection, tooltip rendering, legend swatch all
  updated to use host color where applicable. HostDashSwatch
  → HostColorSwatch.

Verified locally

Upgrade
- Hub: docker compose pull && docker compose up -d
  --force-recreate (or rerun install.sh for the polite flow).
- Master row on the 1h/24h chart starts populating from the
