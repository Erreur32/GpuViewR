release: v0.8.22 rejected-connections panel + agent give-up fix

- Rejected agent connections are now tracked in an in-memory ring
  buffer (bad/rotated token, deleted or unknown host, disabled host,
  flood detection) and surfaced via GET /api/hosts/rejected + a new
  panel in Settings -> Hosts, so a badly-uninstalled agent still
  knocking is visible without grepping hub logs.
- Agent no longer gives up reconnecting forever after a host is
  disabled then re-enabled: the hub now closes with 4003 specifically
  for the disabled reason (was the generic 4001, indistinguishable
  from a genuinely bad token), and the agent stops counting that
  toward its permanent give-up.
- Delete-host modal shows the detected install method next to the
  platform picker (or a warning when unknown), since the wrong tab
  silently hands out a no-op uninstall command.
- install.sh now writes the GPU vendor it detects (GPU_VENDOR,
  ROCM_SMI_PATH) into the agent's env file instead of letting it
  re-probe on its own, which could crash-loop AMD boxes at first
  boot (rocm-smi not on $PATH in a systemd service's environment).
- Fixed npm test silently skipping two nested test files (glob
  didn't expand recursively under the default shell) and corrected
  two Host.test.ts assertions left over from pre-v0.5 behaviour.
