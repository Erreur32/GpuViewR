release: v0.7.7 — Ollama model-name resolution (closes Palier 3 loop)

Resolves the cryptic-sha256 issue left over from v0.7.3: the LLM
badge tooltip now shows "llama3.1:8b" instead of "sha256:a3de86cd"
for Ollama runner processes, once the operator wires the optional
ollama bind-mount.

How it works
- agent/src/collectors/ollamaManifests.ts walks the ollama
  manifests tree on agent boot, parses each manifest JSON, indexes
  the model-layer digest (mediaType
  "application/vnd.ollama.image.model") → tag name
  ("llama3.1:8b").
- The Ollama branch of the LLM classifier (already in v0.7.3) now
  takes an optional resolver param. When the runner cmdline
  surfaces a sha256-XYZ blob path, the classifier asks the
  resolver for that digest's friendly name. Falls back to
  sha256:<prefix> when no match (manifests dir not mounted, model
  pulled bypassing ollama, etc.).
- Refresh on a 5-min interval so models pulled after agent boot
  become resolvable without restart. setInterval unref'd so it
  doesn't keep the process alive.

Discovery picks first existing path from:
  $OLLAMA_MANIFESTS_DIR
  /host/ollama/manifests   (the docker bind-mount target)
  /usr/share/ollama/.ollama/manifests
  $HOME/.ollama/manifests
  /root/.ollama/manifests

Opt-in for docker users
- docker-compose.yaml adds a commented bind-mount to both sidecars
  (nvidia + amd):
    # - ${OLLAMA_DIR:-/usr/share/ollama/.ollama}:/host/ollama:ro
- Left commented to avoid auto-creating an empty /host/ollama dir
  on hosts that don't have an ollama install. Operator uncomments
  + sets OLLAMA_DIR in .env to enable.
- For binary (systemd) agents the feature is automatic — the
  discovery ladder finds /usr/share/ollama/.ollama or ~/.ollama
  with no config.

Internal
- New file agent/src/collectors/ollamaManifests.ts (~170 LOC).
- agent/src/collectors/llmClassifier.ts: new LLMResolvers type
  threaded through Pattern.model callbacks. Backwards-compatible:
  calling classifyLLM(cmd) without resolvers still works.
- agent/src/index.ts: instantiates one OllamaResolver at boot,
  setInterval 5-min refresh, threaded into both process
  collectors via a new `llmResolvers` option.
- Bundle agent.mjs: 185.5 KB → 189.4 KB (+3.9 KB).

Upgrade
- Hub: docker compose pull && docker compose up -d --force-recreate
  (or rerun install.sh for the polite prompt flow).
- For docker agent users wanting friendly names: uncomment the
  ollama mount in docker-compose.yaml + set OLLAMA_DIR in .env to
  your ollama dir (typical: /usr/share/ollama/.ollama or
  /root/.ollama).
- Binary (systemd / Windows) agents pick up resolution automatic
  via the discovery ladder. No config change needed.
