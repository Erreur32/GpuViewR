release: v0.7.2 — GPU% per-process fallback to card global util (AMD/UX)

Patch release. Closes the cosmetic gap left by v0.7.1 on the AMD
side: even with procps installed and /proc mounted, the GPU%
column for AMD processes still showed `-` because the driver
returns cu_occupancy="unknown" from /sys/class/kfd. That's a real
kernel-level limitation we can't fix from the agent, but a `-` is
a poor signal — the user sees 11 GB of VRAM in use and no
indication of compute activity.

This release falls back to the card's global utilization (the same
number the primary util tile shows) when the per-PID gpu_pct is
null. The fallback value renders italic + dim with a `~` prefix
and a tooltip explaining the approximation, so it's visually
distinct from authoritative per-PID readings and the user knows
not to interpret it as a precise per-process metric.

Same fallback fires on NVIDIA when nvidia-smi pmon doesn't see the
pid — same logic, same UI treatment.

Changes
- src/components/dashboard/GpuProcessesTable.tsx:
    - New optional prop `gpuUtilFallback?: number | null`.
    - New <GpuPctCell> helper: authoritative number | approximation
      with tooltip | `-`.
- src/components/dashboard/Dashboard.tsx:
    - Pass `active.utilization ?? null` to the table.
- src/i18n/locales/{en,fr}.json:
    - New `dashboard.processes_gpu_pct_approx` tooltip string.

No agent-side changes; bundle unchanged from v0.7.1 (181 KB).

Upgrade
- Hub: docker compose pull && docker compose up -d --force-recreate
  (only the hub image needs the new bundle — agent is the same).
- AMD users see the GPU column populated with ~card_util% in
  italic; hover for the explanation.
