release: v0.6.4 — install/enroll UX fixes

Patch release closing the four install/enroll UX bugs surfaced
during the .209 redeploy session (post v0.6.3). All four caused
silent failures or confusing error messages that ate ~30 min of
debug time before being root-caused. None changes agent runtime
behavior, so existing agents stay on v0.6.3 and only new
enrollments (or hub-side rotations) benefit.

Fixed
- install.sh.tpl: `--url ws://...` produced `curl: (52) Empty
  reply from server`. The download line is HTTP only (curl can't
  speak ws://). Now derives HTTP_URL from any input scheme before
  the download, keeps WS_URL for the agent env. Both http(s)://
  and ws(s):// are now interchangeable as `--url` input.
- install.sh.tpl: a token without a dot (e.g. a v0.6.3-style
  rotated token) silently passed the existing HOST_ID != SECRET
  check and installed with a wrong host_id that never authed
  against the hub. New explicit `[[ "$TOKEN" == *.* ]]` guard
  bails up-front with a "missing '.' — copy from Add Host modal"
  message.
- server/routes/hosts.ts: POST /hosts/:id/rotate-token now
  returns `<host_id>.<token>` instead of just `<token>`, matching
  the format the install script expects (same as the enroll
  modal). Bcrypt hash is still computed on the raw secret half —
  only the response payload changed.
- scripts/update-version.sh: now bumps agent/package.json
  alongside the root package.json. Without this, the agent build
  was stamping the bundle with the OLD __AGENT_VERSION__, which
  made the hub treat every agent reconnect as "out of date" and
  re-push the same bundle until the 5-min cooldown fired. Had to
  manually bump agent/package.json in v0.6.3; automatic from
  v0.6.4 onward (this release still requires the manual bump
  since the fix can't update its own predecessor).

Why this matters
- Each of the four bugs was a silent failure. The install script
  errors were cryptic ("Empty reply from server") or absent ("the
  service started but is offline forever, no clue why").
  Together they made the "add a new host" workflow a coin flip
  for anyone who didn't memorize the exact http:// + Add-Host-
  modal-token combination. Now any path through the workflow
  either succeeds or fails loudly.

Upgrade
- Hub: `docker compose pull && docker compose up -d`.
- Agents: no change required, agents stay on v0.6.3+.
- Already-rotated tokens: re-rotate after upgrading the hub to
  get a v0.6.4-format token, OR fix the install line by hand
  with `<host_id>.<that_token>` before passing to install.sh.
