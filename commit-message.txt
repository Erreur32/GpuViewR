release: v0.6.1 — agent version visibility + Hosts Type column

Patch release that closes the "which agent version is actually
running on this box" gap left by v0.6.0. The bundle now announces
its real version in the hello frame and at boot, and the Hosts
settings table grows a dedicated Type column so admins can spot
Docker vs bare-metal agents at a glance.

Fixed
- AGENT_VERSION was a hardcoded '0.5.3' string in transport.ts, so
  the v0.6.0 bundle still reported itself as 0.5.3 to the hub and in
  any log line it printed. Esbuild now injects __AGENT_VERSION__
  from agent/package.json at bundle time (same trick the frontend
  uses with Vite + __APP_VERSION__). Dev/tsx runs fall back to
  '0.0.0-dev' via a typeof guard.
- agent/Dockerfile didn't COPY the new agent/scripts/ dir into the
  builder stage; `npm run build` then failed with MODULE_NOT_FOUND
  and the v0.6.0 GHCR push was rejected. One-line COPY fix.

Added
- Boot banner first line shows version + install mode + node
  version so it surfaces under `systemctl status` (last journal
  lines) and `docker logs`:
    "gpuviewr-agent v0.6.1 (docker) starting on node v22.x.x"
- New "Type" column in Settings → Hosts: Docker / Binaire / Hub /
  — (with icons + tooltips) based on the install_mode the agent
  reports in its hello frame. Agents predating v0.5.3 render as a
  muted "—" with a tooltip pointing at the upgrade. Local hub row
  is tagged "Hub" since it has no remote agent.

Upgrade
- Hub image: `docker compose pull && docker compose up -d` picks
  up the new bundle.
- Bare-metal agents: re-run the curl one-liner (or the auto-update
  toggle if enabled) — the hub now serves the patched agent.mjs.
