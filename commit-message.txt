release: v0.7.3 — LLM-aware process classification + hub-agent rename

Palier 3 lands: the agent now identifies which inference stack each
GPU process belongs to and surfaces it as a small badge in the UI.
The README banner shipped in v0.7.0 finally pays off visibly.

Coverage at v0.7.3 (8 runtimes, regex-only classification, ~50
lines):
  - Ollama (CLI + internal runner with sha256 blob path)
  - llama.cpp (llama-server, llama-cli, llamafile, main/server)
  - vLLM (python -m vllm.*)
  - KoboldCpp (koboldcpp.py / .exe)
  - oobabooga / text-generation-webui (server.py --model)
  - ComfyUI (directory-based match)
  - Stable Diffusion WebUI (Automatic1111)
  - LM Studio (lms server, Electron helper)

Wire frame extension is backwards-compatible — two optional fields
(llm_runtime, llm_model) on AgentGpuProcess and the hub's GpuProcess
type. Older agents stay silent; older hubs pass the fields through
without knowing about them. UI shows badges only when llm_runtime
is set.

Bundled with the badge work: a small but breaking docker container
rename. `gpuviewr-agent-local` was always ambiguous on multi-host
setups ("local to what?"). Renamed to `gpuviewr-hub-agent` to make
it explicit that this is the agent shipped with the hub stack, as
opposed to standalone `gpuviewr-agent` containers running on remote
boxes.

Files
- agent/src/collectors/llmClassifier.ts (NEW, ~165 lines incl.
  comments + 8 pattern entries)
- agent/src/collectors/processes.ts: classifier wired in tick()
- agent/src/collectors/processesRocm.ts: classifier wired in tick()
- server/services/_processTypes.ts: GpuProcess fields added
- src/components/dashboard/GpuProcessesTable.tsx: <LlmBadge> +
  label map (Ollama / vLLM / llama.cpp / …)
- docker-compose.yaml: container_name on both nvidia + amd sidecars
- README.md, Docs/V0_5_PLAN.md: container name references updated

Bundle: agent.mjs 181 KB -> 185.5 KB (+4.5 KB for the classifier).

Operator action — IF you have scripts referencing the old container
name (`docker exec gpuviewr-agent-local …`), update them. After
`docker compose up -d --force-recreate` the new name is in effect.

Upgrade
- Hub: cd ~/gpuviewr && docker compose pull && docker compose up -d
  --force-recreate
- The old gpuviewr-agent-local container is removed by compose
  during recreate; the new gpuviewr-hub-agent comes up in its
  place.
- LLM badges appear automatically on the next collector tick for
  any GPU process whose cmdline matches a known runtime.
