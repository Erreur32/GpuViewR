release: v0.8.13 fix AMD process detection for Vulkan/non-KFD workloads

The "Processes using this GPU" tab could stay empty on AMD boxes even
while the GPU was clearly under load. rocm-smi --showpids only sees
processes that opened /dev/kfd (ROCm/HIP compute), so a Vulkan or
OpenGL workload such as llama.cpp built against the Vulkan backend is
structurally invisible to it: it talks to the GPU through /dev/dri
instead and never touches KFD.

Fix
---
- Added agent/src/collectors/processesAmdgpuFdinfo.ts: a DRM fdinfo
  scanner (/proc/<pid>/fdinfo/<fd>, vendor-neutral kernel interface
  standardized since Linux 5.19) that picks up any process holding an
  open amdgpu DRM fd, independent of backend.
- Merged additively into processesRocm.ts: rocm-smi stays the source
  of truth for pids it already reports (keeps cu_occupancy-based
  GPU%), the fdinfo scan only fills in pids rocm-smi misses.
- No new config or env toggle. Degrades to today's exact behavior on
  older kernels or when no amdgpu fd is open.

Scope
-----
Agent bundle only. No hub/frontend changes. No DB migration.
