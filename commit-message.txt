release: v0.7.6 — tsc cleanup, zero errors at repo root

Tech debt drain. `npx tsc --noEmit` was reporting 4 errors at the
start of this session, all pre-existing. v0.7.0 cleared 2 (JSX
namespace move in TS 5). v0.7.6 clears the remaining 2:

1. server/routes/alerts.ts L92/L104/L177 — `req.params.id` cast to
   `string`. Express's untyped Request<> widens params to
   `string | string[]` for backward compat with query-style
   params, but path params are always strings at runtime. Matches
   the existing pattern in server/routes/hosts.ts:143 with the
   explanatory comment.

2. server/services/authService.ts L31 — replaced
   `jwt.verify(...) as JwtPayload` (which TS 5 flags because
   `string | JwtPayload` doesn't sufficiently overlap with our
   custom JwtPayload type) with a defensive runtime narrowing:
   - Reject string payloads (jwt-signed-as-string branch — we
     never sign strings so this is dead code at runtime).
   - Validate `decoded.sub` is a number, `decoded.username` a
     string, `decoded.role` admin|user.
   - Return a freshly-shaped object so the caller sees exactly
     our interface, not the upstream `JwtPayload` superset.
   Hardens against tokens signed with the same secret but a
   different payload shape (cross-app reuse, future schema
   migration, dev artefact).

No behaviour change for valid tokens. Invalid-shape tokens now
return null instead of being passed through with potentially
undefined required fields.
