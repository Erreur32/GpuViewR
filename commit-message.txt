release: v0.5.1 — bare-metal agent fix + install-agent.sh + UX polish

Patch release on top of v0.5.0. Two real bugs in the bare-metal
install path, plus the Docker remote-agent one-liner we'd promised
in the v0.5 plan, plus a couple of UX wrinkles caught in dogfooding.

Fixed
- Bare-metal agent crashed at boot with ERR_MODULE_NOT_FOUND 'ws'.
  Bundle was built with --external:ws, expecting install.sh to
  npm install a node_modules alongside — but it doesn't. Bundle now
  inlines ws (38 KB → 161 KB, acceptable). The optional native deps
  bufferutil / utf-8-validate stay external; ws falls back without
  them.
- Bare-metal install.sh died on AMD hosts with "nvidia-smi not
  found". Pre-flight now accepts either nvidia-smi or rocm-smi.

Added
- /install-agent.sh — Docker remote-agent installer, symmetric to
  install.sh (bare-metal). Auto-detects vendor on the target, pulls
  the matching docker-compose.agent.{nvidia,amd}.yaml from main,
  generates .env from --hub + --token, runs docker compose up -d.
  Hub serves it at /install-agent.sh.
- EnrollHostModal Docker mode now shows the new curl one-liner
  (works on both vendors) instead of the NVIDIA-only docker run
  command.
- install.sh respects $PWD when the user has cd'd into a non-default
  dir. No more need for GPUVIEWR_INSTALL_DIR=/path. Same logic in
  install-agent.sh.

Changed
- install.sh silenced the WARN[0000] noise from Compose v2 by passing
  --progress quiet to both `compose pull` and `compose up -d`.

Upgrade
- docker compose pull && docker compose up -d on the master.
- Bare-metal: re-run the curl install.sh — it pulls the new
  agent.mjs (161 KB with ws inline) from the freshly-pulled hub.
