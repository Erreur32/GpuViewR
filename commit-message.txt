release: v0.8.19 WS close diagnostics + hosts table fixes

Two fixes for the Hosts Settings table: the Status column had no
fixed width so "En retard" reflowed the sibling columns, and the
"last seen" age label picked the live WS sample unconditionally over
the polled host.last_seen (even when staler), showing a misleading
age on a host that was actually online. Both now behave consistently
with effectiveStatus()'s freshest-of-two-signals rule.

Also: close reason was never falling back to '-' (ws passes it as a
Buffer, always truthy even empty), DEBUG is now wired into
docker-compose.yaml so logger.debug() output can actually be turned
on in prod, and WS close code/reason + connection uptime are now
surfaced (warn-level under 5s uptime) on both the agent-hub and
browser-hub layers to chase the host-status flicker that persisted
after v0.8.18 with no traceable regression in the hub's ingest path.
