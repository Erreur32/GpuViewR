release: v0.6.9 — Windows install hardening (Node auto-install, ACL fix, logging, icon)

Iteration release driven by the first real Windows agent install
(VPN'd Win10 against the .210 lab hub). Each fix below maps to a
bug that surfaced during that test run and got patched on the fly,
plus the SVG icon registry the user asked for as a foundation for
future per-platform UI work.

Added
- install.ps1 auto-installs Node 22+ via winget when missing or too
  old. Built-in on Win10 1809+ and Win11; falls back to the previous
  "go to nodejs.org" failure on older SKUs. Refreshes $env:Path
  from Machine + User registry hives after install so node.exe is
  resolvable without a logoff. Mirrors install.sh.tpl's NodeSource
  auto-install on Linux.
- install_mode='windows' propagated end-to-end. Agent's
  detectInstallMode() returns 'windows' on win32. Hub's
  forceAgentUpdate + maybePushAutoUpdate now accept 'windows'
  alongside 'systemd' — launcher.ps1's while-loop swaps
  agent.mjs.pending into place ~5 s after the agent exits, matching
  systemd's RestartSec=5 semantics. New "Windows" pill in
  InstallTypeCell on the Hosts settings page with EN/FR i18n.
- src/components/ui/icons/IconRegistry.tsx: central typed SVG
  registry. Six initial entries (vendor.nvidia, vendor.amd,
  platform.{windows,linux,docker,systemd}) addressable as <Icon
  name="..." size={14} />. Adding a new icon = one record entry.
  Windows icon uses the modern Fluent four-square logo in #0078D4.
- launcher.ps1 (generated by install.ps1) now captures all node
  streams to C:\ProgramData\GpuViewR-Agent\agent.log via `*>>`.
  Previously the hidden SYSTEM task discarded stdout/stderr to a
  void, making crashed agents impossible to diagnose. Final
  install message surfaces the log path as the first diagnostic
  command.
- scripts/check-docker-build.js asserts the four install-distribution
  files exist inside the built image (install.sh.tpl,
  install.ps1.tpl, agent.mjs, install-agent.sh). Codifies the
  v0.6.7 -> v0.6.8 incident lesson: install.ps1.tpl was on disk in
  main but missing from the runtime image because the Dockerfile
  hadn't been updated.

Fixed
- install.ps1 ACL step failed on VPN'd / domain-joined / localized
  Windows hosts with "Impossible de traduire certaines ou toutes les
  références d'identité". Was calling
  FileSystemAccessRule('NT AUTHORITY\SYSTEM', ...) which needs LSA
  to translate the name; some installs can't. Switched to the
  well-known SIDs (S-1-5-18 = LocalSystem,
  S-1-5-32-544 = BuiltinAdministrators) which are
  language-independent and need no resolution. Wrapped the whole
  ACL block in try/catch so a future surprise degrades to a
  warning rather than aborting the install.

Internal
- refactor(modal): replace nested ternaries with mode-keyed lookups.
  SonarCloud flagged three nested-ternary code smells introduced by
  the v0.6.7 modal additions. Same fix in all three places: build a
  Record<InstallMode, string> map up front. No behavior change.
- Dependabot bumps merged: react-router-dom 7.15.1, tsx 4.22.1,
  github/codeql-action 3.35.5.

Upgrade
- Hub: cd ~/gpuviewr && docker compose pull && docker compose up -d
- Linux agents: hub auto-update picks up the new bundle.
- Windows agents (installed via v0.6.7+ install.ps1): the
  launcher.ps1 supervisor will pull the new bundle on the next
  agent_update push; or re-run the install.ps1 one-liner from the
  Add Host modal to redeploy from scratch.
