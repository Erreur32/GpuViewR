release: v0.3.1 — AMD/ROCm agent + hub persistence for remote samples

The remote agent now monitors AMD GPUs via rocm-smi (RDNA3, Strix
Halo APUs, discrete Radeon). The same image serves NVIDIA and AMD;
GPU_VENDOR=auto probes both binaries at boot, with explicit nvidia
or amd available for pinning. Smoke-tested end-to-end on a Strix
Halo / Radeon 8060S Mini-PC pushing samples to a remote hub over WS.

Parity with the NVIDIA agent for: temperature, utilization, power,
graphics clock, VRAM, and GPU processes (pid / name / VRAM / CPU%).
Fields ROCm doesn't expose (memory clock on APUs, fan, PCIe gen /
width / RX-TX, per-process GPU%) come back null — the schema
already permits that.

Agent side
- New _rocmParsers.ts parses `rocm-smi --json` info dumps and the
  --showpids CSV-in-JSON quirk, with a device-ID lookup table and a
  gfx<n> fallback for unknown cards. gpu_uuid is synthesized from
  the PCI bus since ROCm doesn't expose a unique ID like NVIDIA's.
- gpuRocm + processesRocm collectors mirror the nvidia versions'
  contracts. Shared /proc helpers extracted to _procTicks.ts so the
  two paths can't drift on cpu_pct math or cmdline reading.
- docker-compose.agent.amd.yml: /dev/kfd + /dev/dri devices,
  group_add for video/render, /opt/rocm bind-mount, plus
  LD_LIBRARY_PATH so the rocm-smi ctypes loader finds
  librocm_smi64.so.1 inside the container.
- Runtime base bumped to node:22-trixie-slim (glibc 2.41). Modern
  ROCm builds need GLIBC_2.38 / GLIBCXX_3.4.32; bookworm's 2.36
  caused the bind-mounted lib to silently fail to load. Agent now
  ships python3 (full stdlib, not python3-minimal — rocm-smi
  imports json/argparse), tzdata, and libdrm-amdgpu1.

Hub side
- New agentMetricsPersistor service. The agent ingest path was
  emitting samples only to the in-memory bus, so a freshly enrolled
  host appeared online but its /api/gpu/devices returned empty and
  the UI showed "Aucun GPU détecté". Subscriber upserts the device
  row inline, buffers metric rows for a 60 s flush, skips
  LOCAL_HOST_ID (gpuCollector already covers it).
- Main docker-compose.yml: runtime: nvidia + deploy.resources are
  now OPT-IN. The hub starts on any host (AMD, no-GPU, dev laptop)
  in control-plane mode out of the box; uncomment for local NVIDIA
  passthrough.

CI
- docker-publish.yml now builds both gpuviewr (hub) and
  gpuviewr-agent in a matrix with independent cache scopes. The
  agent image reference in docker-compose.agent*.yml finally
  resolves to a real ghcr.io tag — previously it pointed at a
  non-existent image and the only documented install path was the
  bare-metal install.sh.
- agent/Dockerfile stale digest pins refreshed.

Quality
- _rocmParsers.ts clears five SonarCloud findings: the regex flagged
  for super-linear backtracking (S5852) becomes a char-by-char
  walker, optional chains replace the `if (!x || !x.trim())` guards,
  parseRocmPids splits into a top-level loop + helper so cognitive
  complexity drops from 21 to under 15.
- 21 parser tests built from real Strix Halo rocm-smi dumps, 5
  persistor tests with an in-memory SQLite. All green.
