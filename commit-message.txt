release: v0.8.18 throttle device-row writes causing lag flicker

After v0.8.17, hosts (including the local one) kept intermittently
flickering to "lagging". Root cause: agentMetricsPersistor.onSample()
ran a synchronous SQLite write (GpuDeviceRepository.upsert) on every
single incoming sample, per GPU, per host, at 1Hz, forever, unlike
markSeen() which is already throttled. Device metadata almost never
changes tick-to-tick, so this was pure write amplification on the same
single-threaded event loop that processes every other host's WS
frames, including the local sidecar's own since it shares this ingest
path since v0.8. Hosts sending heavier traffic (Linux agents with
process lists) could stall that loop just enough to delay markSeen()
for any host queued behind, explaining why Linux hosts (and the local
one) flickered while the lighter Windows agent didn't. The device-row
upsert is now throttled to the same 60s cadence as the metrics buffer
flush.
