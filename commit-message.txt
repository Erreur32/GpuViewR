release: v0.5.2 — install.sh polish + auto-logout on stale JWT + TLS toggle

Patch release on v0.5.1. Smoothing the rough edges users hit during
the real-world install + reset cycle.

Fixed
- Stale JWT after a hub DB reset froze the UI silently. The new
  JWT_SECRET made the browser-stored token invalid; API returned 401
  but the frontend never reacted. api.ts now intercepts 401 on any
  non-/auth/ path, clears localStorage, redirects to
  /login?expired=1. LoginPage shows an amber banner.
- install.sh leaked WARN[0000] env-var noise on re-installs. .env
  is now generated BEFORE docker-compose.yaml is downloaded, and
  `set -a; . ./.env; set +a` exports the vars into the script shell
  so docker compose inherits them during reconcile. No more warning
  spew before .env lands on disk.
- Removed the --progress quiet workaround. Users now see native
  Compose pull progress (image layers downloading in real time).

Added
- TLS toggle in the Add Host modal. A "Hub uses TLS (wss://)"
  checkbox lets users override the auto-detection. Default is
  inferred from the hub URL host: IP literals / localhost → ws,
  FQDN → wss. Catches the HSTS-auto-upgrade trap where a plain-HTTP
  LAN hub gets bogus wss:// URLs generated.
- "Re-run to update" hint under the install command in the Add Host
  modal. Tells users that re-running the same install.sh /
  install-agent.sh command upgrades the agent — idempotent path.

Validation
- typecheck clean (5 pre-existing errors not touched)
- hub + agent build green
- 39 server tests + 8 agent tests pass
- No new SonarCloud-flagged patterns introduced (nested templates,
  index-as-key, double casts) — pre-flight grep clean for the
  v0.5.1→v0.5.2 diff.

Upgrade
- docker compose pull && docker compose up -d on the master.
- Bare-metal / Docker agents: install.sh / install-agent.sh is
  idempotent, re-run with the same args to pull the new bundle.
