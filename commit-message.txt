release: v0.5.3 — install_mode detection + opt-in WS auto-update

Minor release that closes the "double agent" footgun and ships the
mechanism to keep bare-metal agents in sync automatically.

Added
- Agent declares its install_mode (docker / systemd / unknown) in
  the hello frame. Hub stores it per host (new hosts.install_mode
  column, idempotent ALTER TABLE migration). The Hosts tab "Update"
  pill now shows ONLY the recipe matching the remote — running the
  bare-metal curl on a Docker host used to spin up a second agent
  in parallel. Pre-v0.5.3 agents that can't report their mode get
  both recipes in the tooltip with an explicit warning.
- Opt-in WebSocket auto-update for systemd hosts. New per-host
  toggle (circular-arrows icon next to Rotate/Delete) flips
  hosts.auto_update. When ON for a bare-metal host trailing the hub,
  the hub pushes the new agent.mjs as base64 + SHA256 over the
  existing WS at hello time. Agent verifies the checksum, writes
  /opt/gpuviewr-agent/agent.mjs.new, fsyncs, renames atomically,
  exits → systemd Restart= picks up the new binary. 5 min cooldown
  per host prevents crash-loop amplification. Off by default —
  flipping it grants the hub binary-execute authority on the remote.
  Docker hosts excluded (read-only image layer).

Validation
- typecheck clean (5 pre-existing errors not touched)
- hub + agent build green (agent bundle 163.5 KB)
- 19/22 server tests pass (3 pre-existing v0.4→v0.5 migration
  failures, not touched)
- No new SonarCloud-flagged patterns; commit 13a4d0c green on
  Sonar / CodeQL / Snyk before tagging

Upgrade
- Hub: docker compose pull && docker compose up -d on the master.
- Bare-metal agents: re-run install.sh from the hub (idempotent),
  or enable auto-update once and let the next push happen.
- Docker agents: docker compose pull && docker compose up -d in
  the agent's compose dir.
