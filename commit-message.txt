release: v0.1.7, exports - prometheus / mqtt+ha / influxdb / webhook

Exports and integrations
- Prometheus pull endpoint at GET /metrics, exposing
  gpuviewr_gpu_{temperature_celsius,utilization_ratio,memory_used_bytes,
  memory_total_bytes,power_watts,fan_speed_ratio,clock_graphics_hz,
  clock_memory_hz} with gpu/name/uuid labels per GPU. Returns 404 when
  the exporter is disabled (no scrape leakage).
- MQTT publish: one retained JSON message per GPU on
  <prefix>/gpu<N>/state at a configurable interval. Supports username,
  password, custom topic prefix, and optional Home Assistant discovery
  which auto-publishes homeassistant/sensor/.../config topics so sensors
  register automatically in HA.
- InfluxDB v2 line-protocol push to <url>/api/v2/write with Token auth.
  Configurable measurement name and interval.
- Webhook JSON push (POST or PUT) of {source, timestamp, samples} to
  a configurable URL with custom headers and interval.

UI
- New Settings > Exports & integrations: per-exporter form (toggle,
  URL, credentials, interval, exporter-specific options) with a "Send
  test" button per exporter. Passwords and InfluxDB tokens are masked
  in API responses and only updated when the user types a new value.

Backend
- New server/services/exportService.ts: subscribes to gpuCollector
  'sample', schedules push exporters on per-exporter intervals, manages
  a single MQTT connection, exposes renderPrometheus() to the metrics
  route. Configs persisted in app_config.export_configs.
- New routes server/routes/exports.ts (configs API) and
  server/routes/metrics.ts (Prometheus exposition).
- SPA catch-all regex updated so /metrics is not swallowed by the
  static fallback.
- New runtime dependency: mqtt.

Roadmap
- README roadmap split into Done (Exports v0.1.7) and Planned
  (per-process breakdown, password-reset CLI, CSV export, PWA, email
  dispatcher, multi-host fan-out).
