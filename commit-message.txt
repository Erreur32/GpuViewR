release: v0.7.4 — install.sh respects customisations, warns before destructive ops

Hotfix following v0.7.3 with operator-friendliness improvements.

Two operator concerns prompted this:
1. v0.7.3's container_name rename (gpuviewr-agent-local →
   gpuviewr-hub-agent) means operators re-running install.sh
   would have ended up with a stale orphan container.
2. install.sh was silently overwriting docker-compose.yaml on
   every re-run, blowing away any customisations operators had
   added (port remaps, extra env vars, extra volumes).

Both fixed in this release.

Compose file handling
- If docker-compose.yaml already exists, fetch upstream into a
  temp file, compare with `cmp`.
  - Identical → "already up to date", no prompt, move on.
  - Different → print `diff -u | head -40`, prompt Y/n. On Y,
    back up to docker-compose.yaml.bak.<timestamp> and replace.
    On N, keep existing + print upstream URL for manual merge.
  - No TTY (CI / pure curl|bash without /dev/tty) → default N,
    print URL, keep existing.

Stack-recreate handling
- If `docker compose ps -q` returns any container, list them in
  a table (Service / Name / Status), warn the operator that
  --force-recreate will replace them (5-10 s downtime, ./data
  preserved, orphans removed), prompt Y/n.
  - Y → docker compose pull && up -d --force-recreate --remove-orphans
  - N → exit cleanly with the manual command printed for later
- Fresh install (no containers yet) → no warning, proceed.

The `prompt_yn` helper reads from /dev/tty so the prompt works
even under `curl … | bash` invocations (where stdin is the pipe).
Without /dev/tty (truly headless CI), it defaults to N — the
safer choice for a destructive op.

Files
- install.sh: ~60 lines of new logic around the compose fetch and
  the up -d step. The `docker compose up -d` line itself now uses
  --force-recreate --remove-orphans, but is only reached after
  the operator confirms (or on a fresh install).

No code changes elsewhere. Agent bundle unchanged from v0.7.3.
Image rebuild fires because of the package.json version bump.

Upgrade
- Existing operators on any v0.6 or v0.7 release:
    curl -fsSL https://raw.githubusercontent.com/Erreur32/GpuViewR/main/install.sh | bash
  The installer will prompt twice (compose overwrite, stack
  recreate). Answer Y to both for the standard upgrade.
- Operators with customised docker-compose.yaml: answer N at the
  compose-overwrite prompt to keep your file; the recreate at the
  next step will use it.
- New operators: same one-liner. No prompts fire (no existing
  install to protect).
