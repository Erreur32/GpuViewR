release: v0.8.15 fix nanoid DoS, clear stale pacote alert, dismiss npm-pin false positive

Follow-up security triage after v0.8.14: reviewed the three open
GitHub code-scanning alerts and resolved each on its merits instead
of blanket-dismissing them.

Fixed
-----
- nanoid DoS (GHSA-2v37-7h3g-55p8 / CVE-2026-67213): pinned the
  transitive nanoid dependency (pulled in by postcss) to ^3.3.18 via
  a root package.json "overrides" entry. Versions before 3.3.18 spin
  forever if customAlphabet/customRandom are called with size: 0.
  Build-time only (postcss runs during vite build, never shipped in
  the runtime bundle), but the fix is one line, so fix it properly
  instead of risk-accepting it.

Verified, not re-fixed
-----------------------
- pacote DoS (SNYK-JS-PACOTE-8225084): already patched in v0.8.12 via
  `npm install -g npm@latest` in the hub Dockerfile's runtime stage.
  Rebuilt the hub image locally and confirmed the bundled pacote is
  now 22.0.0 (fix landed in 21.5.1). The open GitHub alert predates
  that fix and never auto-closed; dismissing it as already resolved.

Dismissed as false positive
----------------------------
- Scorecard "Pinned-Dependencies" (npmCommand not pinned by hash in
  the Dockerfile): npm ci already pins exact versions and integrity
  hashes via package-lock.json, Scorecard's static heuristic just
  doesn't recognize that form of pinning.

Scope
-----
package.json/package-lock.json (nanoid override) only. No Dockerfile,
agent, hub, or frontend behavior changes.
