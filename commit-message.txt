release: v0.6.6 — SonarCloud dedupe hotfix

The v0.6.5 hosts-table migration in connection.ts repeated the
same ADD-COLUMN-if-missing pattern three times in a row (one
block per new column: last_update_check_at,
last_update_pushed_at, last_update_pushed_version). SonarCloud
flagged 8.3% Duplicated Lines on New Code (18 lines in
connection.ts at 100%), above the QG's 3% threshold.

Fixed
- server/database/connection.ts: refactored the three ADD-COLUMN
  blocks into a single loop over a [name, type][] array. Same
  idempotent runtime behavior, ~12 fewer lines, no duplication.
  No DB-level change — the columns are still added the same way
  with the same names and types.

Why this matters
- Keeps the QG green so the SonarCloud badge in the README stays
  accurate. Also a sane pattern to reuse next time we add
  multiple columns in one migration.

Upgrade
- Hub: `docker compose pull && docker compose up -d`. No DB or
  runtime change vs v0.6.5 — purely a code cleanup.
- Agents: no change required.
