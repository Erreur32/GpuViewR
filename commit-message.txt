release: v0.7.5 — enable Update now button + auto-update toggle on Windows hosts

v0.6.9 added install_mode='windows' end-to-end (agent detection,
hub forceAgentUpdate + maybePushAutoUpdate accept windows alongside
systemd), but the UI side missed two spots in HostsSettingsTab.tsx:
both AutoUpdateToggle and ForceUpdateButton were hardcoded to
`host.install_mode === 'systemd'`. Result: Windows host rows show
the toggle and button greyed out as "unsupported", even though the
backend was ready to push updates to them.

Replaced both call sites with a new isAgentSelfUpdatable() helper
that mirrors the backend gate exactly: systemd || windows. Anything
else (docker, unknown) stays unsupported as before.

Files
- src/components/settings/HostsSettingsTab.tsx: +helper function,
  two one-line call-site swaps.

Verified locally with `npm run build` (Vite green).

User-facing
- Windows agent rows in Settings -> Hosts now show:
    - auto_update toggle clickable + tooltip says "Auto-update on/off"
    - "Update now" button clickable when host is online
- Click "Update now" to force-push the current hub's bundle to the
  Windows agent. The launcher.ps1 supervisor on the agent picks up
  agent.mjs.pending on the next iteration (~5 s) and restarts node
  with the new bundle.
