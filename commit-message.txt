release: v0.8.1 — per-metric color shade on top of v0.8.0 host palette

Follow-up to v0.8.0's host-colored chart redesign. User feedback:
the 3 metrics for the same host all in the exact same hue
(distinguished only by stroke width) was still hard to read at a
glance, especially on a single-host display.

v0.8.1 layers an HSL lightness shift on top of the host's base
palette colour:
- utilization: base hue (the headline number)
- temperature: same hue, ~18% lighter
- power:       same hue, ~18% darker

Combined with the existing per-metric widths (util 2.25 /
temp 1.5 / power 1.0), the three metrics for the same host now
read as a clear color family — same hue, different shade and
weight. Total mode keeps the metric-colored single-curve
rendering from v0.8.0.

Pre-computed once at module scope (10 hosts × 3 metrics = 30
entries cached in a Map) so there's no per-render color math —
hostMetricColor(idx, metric) is a Map lookup after first call.

Files
- src/components/fleet/FleetChart.tsx: new
  METRIC_LIGHTNESS_DELTA table + hexToRgb / rgbToHsl / hslToRgb /
  rgbToHex helpers + hostMetricColor() with module-scoped cache.
  Two call sites swapped: ChartPlot seriesDefs stroke +
  cursor-tooltip stroke.

Verified locally: tsc 0 errors, vite build green. No tests
affected (chart is pure UI, no test harness).

Upgrade
- Hub: docker compose pull && docker compose up -d
  --force-recreate (or rerun install.sh).
- Visual change immediate; no operator action.
